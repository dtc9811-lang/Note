# prompts/生成章卡.md

> 用途：把 `第十世_第1-70章章纲_重写版v2.md` 批量转成 70 张可执行章卡。
> 用强模型（Opus/大参数）做这件事，不要用轻量模型。

---

## 提示词

```
你在为《百世飞升》第十世做写作执行准备。

现在给你章纲的第X段（附后），请把它拆成逐章章卡，一章一张，严格用下面的格式，
不要写正文，不要新增设定，不要新增人物。

【章卡格式】
# 第___章　章名：__________
档位：
地点：
在场人物：（写全名，人数=___）
节拍：
1.
2.
3.
（3—6条，按顺序）
修炼节点：
- 本章修为有无变化：
- 若是突破章：从__→__，代价是__，当场用出来做了什么__
信息变化：
- 读者新知道：
- 赵升新知道：
- 其他人新知道：
- 不能让谁知道：
本章禁区：
- 不能出现：
- 不能提前揭露：
结尾钩子：
类型：
具体一句：

【硬性要求】
1. 地点要写死，一章原则上不换地图。
2. 在场人物必须写全名，必须给人数，方便后文守恒。
3. 节拍要写成"发生什么"，不要写成"要表现什么"。
4. 修炼节点没有就写"无"，有就写清楚数字和代价。
5. 本章禁区必须至少写一条。
6. 每张章卡控制在 300 字以内。
7. 只输出章卡，不要输出解释。

【章纲第X段】
（粘贴章纲对应段落）
```

---

## 分批建议

| 批次 | 章号 |
|---|---|
| 1 | 1—13 |
| 2 | 14—25 |
| 3 | 26—40 |
| 4 | 41—55 |
| 5 | 56—70 |

每批生成完，人工核对：
- 人数有没有前后矛盾
- 修炼节点有没有漏
- 有没有把不该揭的提前揭了

# prompts/生成交接卡.md

> 用途：每章正文写完后产出交接卡。
> 可以直接用轻量模型做，但要求它只输出交接卡，不重写正文。

---

## 提示词

```
下面是第X章正文和本章章卡。请只输出【交接卡】，不要重写正文。

【交接卡格式】
【第X章交接卡】
1. 已发生的事实：
   -
   -
2. 各人所知：
   - 赵升知道：
   - 在场其他人知道：
   - 不知道的人：
3. 当前错误答案：
   - 众人以为：
4. 未兑现的细节：
   - 物件：
   - 伤势：
   - 承诺：
   - 伏笔：
5. 本章结束时的可见状态：
   - 地点：
   - 在场人数与姓名：
   - 每人手中关键物品：
   - 刚发生的物理变化：
6. 下一章禁区：
   -

【要求】
- 只写正文里确实出现过的内容，不要推测，不要补充。
- 300字以内。
- 不准写"大概""似乎""可能"。

【本章章卡】
（粘贴）

【本章正文】
（粘贴）
```
