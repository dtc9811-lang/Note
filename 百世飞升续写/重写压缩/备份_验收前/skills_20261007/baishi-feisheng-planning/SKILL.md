# 《百世飞升》第十世规划

规划必须建立在已验收正文事实、DevTrace 当前裁定和人物承载能力上。不要凭旧总纲或修仙套路补设定。

## 开工入口

1. 调用 DevTrace `resolve_workspace(cwd="F:\\novel")`，再对最相关的 active Task 调用 `get_task_context`。
2. 读 Task 的 `current_conclusion`、`current_risk`、`next_step`、最近 `decision/risk/finding/test`；预览不足时再用 `get_events`。
3. 在 `F:\novel\百世飞升续写` 运行 `python 脚本/正文管理.py 状态`，确认正式正文尾章。
4. 判断当前阶段：
   - 正式续写：`分章/` 是连续性真源，读最后三章。
   - 重写候选或尚未并入正本的续写：`分章/` 仍是已发布真源，但其后的**已验收候选章**构成暂存连续性；规划下一章时读最近三章已验收候选稿。未验收稿只能作为待审目标，不能反向定设定。
5. 读 `F:\novel\AGENTS.md` 与本次规划所需的最小资料集。

## 事实优先级

发生冲突时按以下顺序裁定：

1. `分章/` 正文事实；若处在候选续写阶段，再接 DevTrace 标为通过的候选正文
2. DevTrace 当前 Task 与较新的 `decision`
3. `写作资料/02_设定总表.md` 的固定设定
4. 已确认的人物、对手、配角与批次规划
5. `写作资料/03_长期总纲.md`
6. 历史备份、旧章卡、候选稿

后项不能静默覆盖前项。冲突无法由现有证据裁定时，标成占位或 `risk`，不要替作者补答案。

## 资料路由

任何规划都读：

- `F:\novel\AGENTS.md`
- 当前 DevTrace Task 与最近裁定
- `写作资料/02_设定总表.md` 中与目标章有关的段落
- 当前卷施工单、批次契约、相关工单条目
- 最近三章已验收正文或候选正文

按任务追加：

- 章节施工单：读 `写作资料/01_写作规则.md`、`03_长期总纲.md`、`04_前情与伏笔.md`、`规划/当前批次索引.md`。
- 人物去留：读 `规划/人物轮换规划_第十世.md`、`规划/人物承载审核_第十世.md`，并在正文中检索修为、寿元、伤势、利益与自主行为；再读 [人物承载与轮换检查](references/character-gates.md)。
- 主要对手：读 `规划/对手梯度规划_第十世.md` 与 [对手梯度检查](references/antagonist-gates.md)。
- 可迭代配角：读 `规划/可迭代配角规划_第十世.md` 与 [可迭代配角检查](references/supporting-character-iteration.md)。
- 旧号换算：读 `规划/旧号新号映射表.md`。
- 重写候选：读目标章的 `重写压缩/工单/条目/`；不要把 `归档/`、备份或未点名的 `待处理/` 当正史。

不要为普通单章规划整包读取全部人物规划、全部旧稿和所有备份。


## 宏观模式与施工模式

开始规划前先判断任务属于哪一层：

- **宏观规划模式**：整阶段、整卷、新地图切换、长期主线修正、人物/修行/法宝/探险/重大事件/大世界联动设计。此模式先读 `F:\novel\百世飞升续写\规划\宏观规划规范.md`、`写作资料/03_长期总纲.md`、`写作资料/05_第九世与第十世对比.md`，先做20—30章尺度的3—5件大事和八维规划，**禁止直接拆单章**。宏观Gate通过后，才能进入批次与施工单。
- **施工规划模式**：宏观方案已拍板后，继续使用本 Skill 原有的人物承载、对手梯度、节奏、事实包、20%—30%自由区和DevTrace回写规则，拆5章批次或下一章施工单。

若用户说“先从大方向”“整卷怎么走”“规划这一世/这一阶段”“人物、修行、法宝、探险、大世界怎么安排”，默认进入宏观模式。

宏观模式必须覆盖：人物、修行、法宝/资产、探险、重大事件、大世界、因果链、奖励密度八维；不能只设计规则题、对手或章节节拍。

## 规划门槛

### 人物

持续同行者必须证明：活得了、跟得上、有自己的事。核对修为/资质、寿元、环境耐受、利益、自主目标、保护成本、退出点与回归条件。依据不足就安排留下、分路、死亡、闭关或转为远端节点。

主角保护只能解释一次短途同行，不能支撑长期跨地图、跨界域、跨百年常驻。不得临时补隐藏血脉、高资质、无代价点化或洞天常驻。

### 对手与配角

主要对手要有第一胜、旧解法失效、逼出的成长和不可逆退出；旧对手原则上不跨地图继续担任主对手。每个主要地图分别安排主动伤人的敌手、利益对手和规则环境。

可迭代配角必须在离开赵升视野后完成独立任务；回归时身份、能力、信念、关系、代价至少两项变化。同阶段活跃池不超过八人，每卷重点推进两人。

### 节奏

每章至少有一个不可逆结果，并兑现至少两类脉冲，其中至少一类属于世界、修炼、战斗、探索、收获。检查五章一硬、十章一换、主要地图二十至三十章上限。连续三章同地点、同冲突或只在讨论记账，下一章必须换玩法。

## 章节施工单写法

施工单只锁：

- 章节目标与不可逆结果
- 必须延续的事实、数字、伤势、物件归属和信息边界
- 三至六条节拍方向
- 本章兑现的脉冲
- 禁区与不能提前揭露的内容
- 章末落点类型
- 允许写手自由发挥的范围

不要写逐动作分镜，不要预设普通小动作，不要把自查用的“不许清单”写成可被正文照抄的完整句子。修炼、战斗、硬规则和数字守恒场可以收紧，但仍保留至少一处场景展开自由。

每张施工单同时给写手一个小型“事实包”：

- 开场时人物、地点、伤势、修为与物件状态
- 本章可以新增的长期事实、专名和剧情数字；没有就写“无”
- 角色本章知道什么、不知道什么
- 与下一章衔接时必须留下的可见状态

事实包只约束后文需要记住的内容：人物身份与能力、地点和机构、物件来历与归属、修为伤势、日期距离钱数、人数资源量、规则和长期关系。不要把它扩张成对所有现场细节的审批。

施工单可另外声明一至两类“临时台账自由位”，例如本地脚户、短期交易者、小冲突、局部线索或普通物件去向。只锁它们不能改变的主线边界，不替写手预设姓名、动作与唯一结果。写手可用 MCP `story_register/story_handoff` 自行创造并在五章内交接、结清；规划者不把这些临时卡提前升级为长期设定。

施工单必须明确给出 20%—30% 的真实自由区，通常至少选两项交给写手：场景从哪里切入、同一组节拍如何排序、无名路人的临场反应、既有地点内的普通物件与声响、对话攻防的具体走法、局部失败或误会如何发生。只要这些细节在本场闭合、不改变硬事实、不要求后文记账，就不必预先列出。

施工单锁的是因果功能，不锁唯一实现。若“谁作出选择、付出什么代价、最后留下什么状态”不变，写手可以采用更自然的等效场景或动作完成节拍，并在交付说明里报告偏离。

## 交付与回写

先列已核实事实，再给方案。未确认姓名、数字或设定明确标为占位/待裁定。

有意义的规划必须写回 DevTrace：章节施工单用 `note`，长期口径用 `decision`，未解决矛盾用 `risk`，正文查证结论用 `finding`。同步仍成立的 `current_conclusion/current_risk/next_step`。

若规划改变人物进入/退出、地图去向或长期关系，同步对应卷施工单、工单条目和人物规划；不要只改一处。规划结束时明确交给写手的目标文件与验收关口。

故事台账只承接短期自由发挥，不替代 DevTrace `decision`、设定总表、人物规划与批次契约。临时卡需要跨五章或跨卷时，必须重新经过人物承载/宏观因果审核，先记 `decision` 再提升为长期正史。
