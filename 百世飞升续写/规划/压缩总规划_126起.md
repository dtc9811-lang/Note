## 二、慢在哪里（三层）

### 1. 结构层：刻度切得太细

- **修为半成一跳**：三成→四成→四成半→五成→五成半，每跳隔 9—10 章。照这个刻度，醒到十成（重回长生真仙）还要约 11 跳、100 章，之后还有洞天四阶段和金仙。
- **世界三轴 + 修为轴各自一格一格走**：界域 8 级、路网 7 级、仙籍 7 级，每格都要单独的章去兑现。
- **一个地图 20—30 章是下限，不是上限**：无归渡生态已经撑了约 90 章（路线图自己记的超期）。

### 2. 流程层：规划比正文还重

- **一章一个完整循环**：Flash 施工单 → Qwen 正文 → 两个脚本 → Flash 验收 → 更新索引。120 的施工单卡了约 20 小时（索引第六节自记）。
- **规划文档体量**：`规划/` + `待处理/` + `写作资料/` 共约 364KB；`全本.txt` 约 729KB。设计包和落单条件表加起来约 18 万字节，只覆盖 122—149 这 28 章。
- **章节被设计包卡住**：125—126 待 B 线第四项、133 待 C 线条件、143 待 C 线数字、145—147 待 D 线——正文写手经常在等规划。
- **三条写手线并行**（W1 正文、W2 旧章、W3 设计），但真正推进故事的只有 W1。

### 3. 章节层：单章事件量小

- 120—125 六章，故事时间约 10 天：换纸、认货、赶路、寻墟、一场遭遇战、守候者露面。其中大量笔墨花在饼、水、炒面、骡子等赶路细节上。
- 赶路本身没有冲突时，也逐日写。

## 六、流程压缩（比剧情压缩更关键）

| 现行 | 改为 |
|---|---|
| 一章一循环（施工单→正文→脚本→验收→更新索引） | **一批 5 章一循环**：Flash 一次出 5 行式章纲（每章一行：事件/不可逆点/落点）→ Qwen 连写 5 章 → 脚本 → Flash 一次验收 5 章 |
| 设计包 + 落单条件表，每批 3—4 万字节 | **每卷一份卷纲 ≤5KB**；只给 H 档节点章另写 ≤1KB 的节点卡 |
| B/C/D 三条设计前置线 | 停。卷纲在开卷前一次写完即可 |
| W2 旧章维护线 | 暂停，等卷〇收官后再按第七节一次处理 |
| 03 总纲 + 路线图 + 批次索引三份 | 合成一份"卷纲"，DevTrace 只记每批一条 note、一条 test |
| 赶路逐日写 | **无冲突的赶路、日常、补给，一段概述**；逐日写只给有冲突的日子 |
| 每 5 章至少一次战斗或收获 | 保留；另加：**每章故事至少推进一条进度线（修为/世界/谜底/敌我）** |
